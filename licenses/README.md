# Third-party license resources

- `Pi-Coding-Agent-0.85.1-MIT.txt` is the MIT license from the exact Pi source tag bundled by this repository (`v0.85.1`): <https://raw.githubusercontent.com/earendil-works/pi/v0.85.1/LICENSE>.
- `pi-runtime/0.85.1/npm-shrinkwrap.json` is Pi's official v0.85.1 published runtime lock. `scripts/pi-version.json` pins its upstream URL and SHA-256; the release prebuild verifies its version and direct/optional dependencies against the embedded Pi package manifest, then stages an OS/CPU-filtered Syft-readable lockfile under `.cache/` for a separate per-platform Pi runtime SPDX SBOM. The source lock lists 164 transitive runtime package entries under seven declared SPDX license identifiers/expressions and is included in the app's `licenses/` resources. This dependency set is not literally all MIT: it includes 0BSD, Apache-2.0, BlueOak-1.0.0, BSD-3-Clause, ISC, MIT, and Unlicense; the package-specific release notices must preserve that license information.
- `pi-runtime/0.85.1/third-party-notices.json`, `THIRD_PARTY_NOTICES.md`, and `third-party/` are generated from the verified runtime shrinkwrap during `prebuild`. The collector uses the union of Windows x64, macOS x64, and macOS arm64 package entries, verifies every available npm tarball against its lockfile SRI digest, and includes every package's license text. Where a tarball omits its license file, the index labels the fixed SPDX License List v3.29.0 canonical text; five Pi monorepo packages without registry integrity use the Pi v0.85.1 repository MIT license. This is license-text coverage, not a review of every package-specific copyright or additional notice.
- `spdx/3.29.0/` contains the canonical license texts used for explicitly labeled fallbacks by the Cargo and Pi runtime notice collectors. Sources are the SPDX License List v3.29.0 text directory: <https://github.com/spdx/license-list-data/tree/v3.29.0/text>.
- `FiraCodeNerdFontMono-3.4.0-OFL.txt` and `LXGWWenKaiLite-1.522-OFL.txt` are the upstream SIL Open Font License texts for the bundled terminal and CJK fonts. Their fetch scripts copy the verified source license into this directory on every build, including when the font assets are already cached.
- `public/vendor/esbuild-wasm-LICENSE.md` carries the license for the bundled offline TypeScript compiler WASM.
- The frontend build emits `public/vendor/licenses/THIRD_PARTY_NOTICES.md`, copies root license files for packages found in esbuild's browser bundle inputs, and emits esbuild `.LEGAL.txt` files for recognized license comments. This inventory is regenerated from installed, locked packages at build time; packages with a declared license but no root license text are called out in the generated index.
- The Tauri bundle includes this directory as `licenses/` on each platform; the complete `public/` tree is also bundled.
- The desktop build workflow is configured to generate and upload a per-platform SPDX JSON build-dependency SBOM from the repository after building the installer.
- `bun run licenses:cargo` generates `licenses/cargo/<target>/THIRD_PARTY_NOTICES.md` and deduplicated crate license texts for the selected `PIPLINE_CARGO_TARGET`; desktop packaging sets this to each Windows/macOS target before Tauri reads the `licenses/` bundle resource. If a crate source archive omits license text, the collector may use checked-in canonical texts from SPDX License List v3.29.0 only when every identifier in the declared expression is available; it refuses unknown identifiers and `WITH` exceptions, and labels SPDX fallback sources in the package index. When a crate declares conjunctive `AND` licenses and its local source contains only some license texts, the collector supplements those local files with the canonical texts for the declared expression. These standard texts do not replace review of crate-specific notices or Pi Runtime binary dependencies.
- The current Windows build identified 58 npm packages in browser bundle inputs and copied their license texts; esbuild also emitted separate notices for recognized bundled comments. `@xterm/addon-serialize` declares MIT but omits a root license file from its npm package, so the generator explicitly includes the shared xterm.js upstream MIT license and labels that source in the index. The SBOM workflow has not yet run in Pipline's own GitHub repository. Pi's bundled implementation dependencies and the packaged installer contents still require a release-wide license review before public release.
- Cargo source bundles do not include a license text for every crate. For the current locked targets, SPDX fallback yields complete text coverage in the generated Cargo index; package-specific notices still require release review. The collector resets only the selected target's output directory, preserving other platform indexes when run repeatedly.
- A 2026-09-27 metadata audit of the checked-in Windows x64, macOS x64/arm64 Cargo notice indexes, the Pi v0.85.1 shrinkwrap, and the generated browser-bundle notice index found no declared AGPL/GPL/SSPL package expressions. The phrase “GNU Affero General” appears inside the MPL-2.0 license text used by `cssparser`, `cssparser-macros`, `dtoa-short`, `option-ext`, and `selectors` as a compatibility reference; it is not their declared license. This metadata/text search does not independently audit every object linked into the compiled Pi binary, so release SBOM and binary provenance review remain required.
- Cargo dependency-tree inspection shows `option-ext` is reachable through Tauri's normal dependency graph (including the app's `dirs` dependency); the `cssparser`/`selectors` family is reached through Tauri utility/code-generation and proc-macro paths. The Cargo license collector now copies every MPL-2.0 crates.io source archive in the selected target graph into `licenses/cargo/<target>/mpl-source/`, after verifying its SHA-256 against `src-tauri/Cargo.lock`, and emits an archive index. The five current Windows/macOS archives total about 150 KB per target. Before public closed-source distribution, still review the target linkage and confirm the applicable notice/source-availability obligations; the presence of these archives is evidence of source availability, not a legal conclusion.
