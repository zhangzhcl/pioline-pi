# Pipline project context

Pipline is an early-stage desktop coding workspace based on the MIT-licensed Picot Tauri app. It integrates the official Pi Coding Agent through the bundled `pi --mode rpc` runtime and renders Pi messages, tool calls, and status in a desktop UI.

## Product decisions

- First targets: Windows 10 x64; macOS 11.0+ on Apple Silicon and Intel.
- Bundle the platform-specific Pi Runtime in each installer; never require users to install Pi CLI, Node, or Bun. Windows/Linux use the official compiled Pi runtime. macOS uses the official Pi Node package and embeds a checksum-pinned Node 22 LTS binary because official Pi macOS binaries require macOS 13 while Pipline supports macOS 11.
- Reuse `~/.pi/agent` for Pi auth, settings, extensions, and sessions.
- Resolve Pi-owned paths through `pi_agent_dir`: `PI_CODING_AGENT_DIR` is the explicit override, otherwise use `~/.pi/agent`. Pass the same resolved directory to the embedded Pi subprocess and use it for Host session discovery, startup recovery, Agent Inbox sessions, global Pi settings, and the sibling `.pi/picot-runtimes` child-supervision registry. Resolve the default workspace home separately from Pi's agent directory (`USERPROFILE` on Windows, `HOME` on Unix), so a custom Pi config path never changes the user's default project directory. Pipline-owned workflow data remains in the application data directory.
- Keep Pipline workflow definitions and runs in Pipline's own application data directory.
- Ordinary chat stays free of workflow prompts and the workflow canvas runtime.
- Workflow mode shares one versioned state between the Pi conversation tools, canvas, and scheduler.
- The workflow editor is a dedicated Tauri window (lazy-loaded), not a narrow sidebar; it shares the same Host/SQLite workflow and run state with the conversation window.
- All workflow UI is localized through Pipline's global locale resources. Built-in and custom node labels, descriptions, ports, parameters, options, statuses, logs, and errors follow the app language; persisted IDs and execution values remain locale-independent.
- Do not copy or add dependencies on `wangmiaozero/pi-harness` source.
- Apple Developer ID and notarization are deferred release tasks.
- macOS 11's WKWebView is the frontend compatibility floor: all application entrypoints are bundled as Safari 14-targeted native ES modules with relative chunk imports, and an early local compatibility script fills missing APIs (`structuredClone`, `Object.hasOwn`, and `Array.prototype.at`). Keep the CSP limited to same-origin scripts; do not load source modules through blob-based shims or assume a current Safari/WebKit engine on the minimum supported OS.

2026-09-28 M4 Run event-history replay: the previous loader checked event sequence/identity and the last event type, but a tampered intermediate payload could still disagree with the persisted node state. A SQLite regression reproduced acceptance of a `node_started` event while its node remained idle. Run detail loading now replays events from the queued/idle initial state through the same Host delta validator, then compares replayed status/result/error/nodeStates with the stored snapshot. Interrupted recovery's terminal node transitions follow the Host and persistence-failure reconciliation contracts. Replay also exposed that writes did not require Run `updatedAt` to match its event timestamp; append now rejects mismatches so it cannot persist records that its own loader would reject. Event payload validation requires `run_completed.result` (explicit null is valid) and a nonempty `node_skipped.reason` in both append and replay. Queued and running restart recovery both load as replayable interrupted Runs. Replay is limited to detail loads; Run lists retain lightweight index-summary checks. Full `bun run check:rust` passes: cargo check, Clippy with warnings denied, 311 Rust tests passed / 2 ignored, and fmt. Workflow UI and cross-window recovery acceptance remain open.
